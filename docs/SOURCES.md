# Source matrix and coverage

Milestone 0 asks for a source matrix, real-versus-fixture coverage, and proof that one input causes at most one read. This file tracks the first two. The third is covered by `CaptureGateTests` and the live counters in the status bar.

The source ledger below comes from the project handoff spec (reviewed 27 November 2026). **Apart from rows 1 and 17, it has not been re-verified in this repository.** Row 1 was checked against GGG's live policy page on 27 November 2026: see [GGG's third-party policy](#ggg-third-party-policy-checked-27-november-2026). Row 17 was added and checked on the same day. Recheck each source before a release and whenever a pack or provider changes.

## GGG third-party policy (checked 27 November 2026)

Source: [pathofexile.com/developer/docs](https://www.pathofexile.com/developer/docs), section "API Policies and Third-Party Requirements". The page carries no version or effective date, so it can change without notice; recheck it after the 11 December 2026 full release (#2). Its quotes below are verbatim. The Terms of Use sections it cites (7b, 7c, 7i) were not re-read.

| What the policy says | What SSE does |
|---|---|
| "Executable apps that run independently from the game": "While not encouraged, these are permitted." | SSE is a separate process. It never loads anything into the game. |
| "Executable apps that interact with the game or game files": "Creation or use of these type of applications will result in immediate account termination." | SSE never reads or changes the game's memory or files, and never modifies the client. |
| "Apps that use information sourced from the screen, the clipboard, or the game's logs must follow our overlay rules:" "You may only read this information as long as the user is aware of what you are doing with that data." "Reading from the screen or clipboard may only be performed once per manual key press." | One clipboard read per physical press: auto-repeat and synthetic input are ignored (`CaptureGate`, `CaptureGateTests`). Settings and onboarding say exactly what each key reads. The game's logs (`Client.txt`) are not read: the policy does not say whether they count as "game files", so the guide takes the zone from the player instead. The stash picture collector (off until the player switches it on, and described in Settings) reads at most one frame of the game window per physical press of the stash key, through the same gate; the planned stash and Aldur labels must keep to that too (#4). |
| "Automation of key-strokes (or other inputs) that affect the game in any way must follow our macro rules": macros "must be invoked manually by the user", each with "one set function", and the result "may only perform one action that interacts with the game". | SSE sends no input to the game at all; the status bar shows "Keys sent to the game: 0". The player presses `Ctrl+C` and the game copies. Moving focus back to the game when the `F3` window or a kept-open card closes is a focus change, not input. |
| "Every public or widely available application should include some form of the following statement in a visible location: This product isn't affiliated with or endorsed by Grinding Gear Games in any way." "You may not present your project or tool in a way that could be construed as it being developed or officially authorised by Grinding Gear Games." | The statement is in Settings → Data and privacy and at the end of the README. |
| "We don't encourage players to download or run "tools" on their machine..." "Introducing features against these guidelines or our Terms of Use can result in account termination for you as well as your users." | GGG approves no tool in advance, so following the rules lowers the risk but cannot remove it. Every new feature is checked against this table before it ships. |
| Not addressed: drawing over the game (the page refers to "overlay rules" but has no separate overlay section), screen capture as such, and low-level keyboard or mouse hooks. | The HUD windows are click-through and never take focus, except a quick price card the player keeps open by moving the mouse onto it while holding the key: it then takes clicks, and the focus only when clicked. Noticing that reads the cursor position, not the screen, and only while the key is held. The hooks only observe and always pass every event on. |

## One input, at most one read

- `CaptureGate` (domain) allows a read only on the first physical key-down after a key-up, only while the game (or SSE itself, in demo practice) is in front. Auto-repeat and synthetic input are ignored. Late results are dropped by generation id.
- `CaptureGateTests.Ten_second_hold_with_autorepeat_reads_once` holds the key for 300 auto-repeat events and asserts exactly one read and zero game actions.
- The status bar shows the live counters. The HUD path has no HTTP client, so market requests from a key press are 0 by construction (`LivePricesTests.The_HUD_has_no_way_to_reach_the_network` checks it). Live prices are fetched on an hourly timer instead and only read on a press.
- Screen frames: `FrameReader` puts the same gate in front of a one-frame capture, discards the frame after analysis and drops late results. So far only the stash picture collector (Settings, **Collect stash pictures**, off by default) uses it: one frame of the game window per physical press of the stash key, saved for #3 (`StashCollectorTests`, `RealCaptureTests`). Backends, latency and the one-press-one-frame evidence from the #4 spike are in [Capture spike](CAPTURE-SPIKE.md).
- Still to do on real hardware: a timed trace in the game at 1080p, 1440p, ultrawide and 4K, mixed-DPI monitors and 100/125/150% scaling.
